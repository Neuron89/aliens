# MU/TH/UR — Expandable Tabletop Game System: Architecture

This document is the contract every contributor (human or agent) builds against.
Read it fully before touching `web app/`.

## Goals

1. **Universe-agnostic engine.** The app is a real-time game-master terminal. ALIEN RPG is the
   first universe; Dune is the second; more will follow. Nothing universe-specific may live in
   shared components. Everything universe-specific lives in `src/universes/<id>/`.
2. **Content packs are data, not code.** Scenarios, characters, NPCs, handouts and maps are JSON
   documents validated against a schema. They can be bundled, dropped into a folder at runtime,
   imported through the UI, or generated by Claude from parameters.
3. **Game Night flow.** DM picks a universe, picks or generates a scenario pack, players join on
   phones, play, pause, resume.

## Universe module interface

`src/universes/<id>/index.js` default-exports the object below. It is built as
`{ ...core, rules: { ...core.rules, dice: { ...core.rules.dice, Roller } }, navSections, maps (engine components attached), content: { packs } }`
where `core` is the default export of `src/universes/<id>/universe.core.js` — a JSX-free module
(no React, no `import.meta.glob`) that `scripts/smoke.mjs` imports in node. Every universe must
provide both files.

```js
  name: 'ALIEN RPG',
  tagline: 'In space, no one can hear you scream.',

              statusLines: ['SYSTEMS NOMINAL','CREW MONITORING','UPLINK ACTIVE'] },
```

Newer keys, all optional unless noted (full field lists in `docs/ADDING_A_UNIVERSE.md`; each shipped universe provides what it needs):

- `catalog` (in core): data from `catalog/*.json`, read through `src/engine/catalogUtils.js` (`getCatalog`, `startingGearFor`, `encumbrance`, `armorRating`, `skillPool`, `effectsFor`). ALIEN also has `catalog.panic`. Used by the character builder/sheet, the board palette and the threat cards.
- `rules`: `panic { die, table, stressAdd, statusAt, actionAt, statusEffect }`, `supplies[]` + `supplyMax` + `supplyDanger` (ALIEN), `pools[]` (DUNE: `key label max initial owner visibleToPlayers playerAdd initialPerPlayer resetOnNewSession`),
  `initiative { mode: 'cards'|'nominate', ... }`, `encumbrance { formula, overFormula } | null`, `creation` caps (`keyAttrMax otherAttrMax skillMin keySkillMax otherSkillMax talents allowGeneralTalents careerKinds`).
- `terms`: `sessionArticle career attributes skills talent gear` (the builder and sheet use them; DUNE: Archetype, Drives).
- `theme`: `motif` (`deckplan`|`contours`, landing card art), `overlay` (`crt`|`grain`, sets `html.overlay-<name>`), `overlayCss` (injected as `<style id="universe-overlay">`), `favicon` (inline SVG), `board` (table-board palette, `levelNoun`, `backdrop`; `board.reveal` also picks the cinematic camera's edge: `scan` → CRT, `dust` → heat shimmer), `sfx` (synth recipes per sound id),
  `ambient` (ordered ambience preset ids shown in the rail AUDIO popover, e.g. ALIEN `['ship','derelict','hive',…]`, DUNE `['erg','wind','sietch','keep',…]`),
  `sounds` (soundboard: `{ stingers: [ids in button order] }`, ids from `src/engine/soundboard.js` `STINGERS`; ALIEN `klaxon hull-groan airlock steam-vent tracker-burst screech lights-out`, DUNE `worm wind-gust thumper shield ornithopter crysknife voice`),
  `handoutStyle` (`teletype` | `filmbook`; otherwise derived from `overlay`: `crt` → teletype).
- `features` (in core): optional engine features, absent = off. `features.tracker: true` (ALIEN) gives phones the TRACKER tab, the GM's CREW drawer the GRANT/REVOKE TRACKER control, and enables the server's `tracker-set` / tracker view for games in that universe (the server reads it from `universe.core.js` at start).
- `maps[]`: board geometry per `docs/BOARD_AND_BUILDER.md` section 3 (`kind size levels rooms doors spawn grid outline crop levelNoun backdrop palette`).

`theme.vars` must define at least: `--bg-dark --bg-panel --bg-card --bg-input --border --border-bright
--border-glow --text --text-dim --text-bright --accent --accent-dim --accent-glow --accent-bright --warn
--warn-dim --danger --danger-dim --danger-glow --success --blue --purple --font-display --font-mono`.

Shared components must only read these fields. If a universe needs something new, add it to
this interface and to **every** universe (with a sensible default), then to the components.

## Content pack schema (v1)

A pack is one scenario plus everything needed to run it. Characters are embedded so a pack is
self-contained. Required fields marked with `*`.

```jsonc

  "id": "derelict-signal-7c",                // * kebab-case, unique per universe
  "universe": "alien",                       // * registry id
  "kind": "scenario",                        // * "scenario" | "campaign" | "characters" | "maps" (overlay pack "<packId>-maps")
  "meta": {
    "title": "...", "tagline": "...",        // *
    "synopsis": "GM-facing overview",
    "type": "Cinematic",                     // Cinematic | Campaign | One-Shot
    "players": "3-5", "playtime": "3-4 hours", "difficulty": "Standard",
```

Character object (universe-shaped, but these keys are always present):
```jsonc
{ "id": "...", "name": "...", "career": "...", "appearance": "...",
  "attributes": { "<attrKey>": n }, "skills": { "<skillKey>": n },
  "talent": "...", "gear": ["..."], "signatureItem": "...",
  "personalAgenda": "...", "buddy": "...", "rival": "...",
  "secret"?: "...", "agendaByAct"?: { "1": "...", "2": "...", "3": "..." },
  "driveStatements"?: { "<attrKey>": "one sentence in the character's voice" } }       // DUNE drives
```
`health` is derived by `universe.rules.derived.health(char)` at assignment time; packs may
include it (optional integer) but the engine recomputes. Bundled ALIEN packs omit it.

Custom characters made in the creator are stored in a runtime pack with id `custom-characters`,
`kind: "characters"`.

The JSON Schema in `server/schema/content-pack.schema.json` is the source of truth; keep this
doc and the schema in sync. Validation runs on every save and on every generator response.

`relations[]` (optional, on NPCs and characters, ≤ 12 each): `to` = an NPC name, character name or character id of
the same pack; `kind` = `ally | rival | owes | fears | loves | serves | hides`; `note` ≤ 300 chars (GM-facing, safe to
reveal); `secret: true` = drawn dashed in the GM's intrigue web until revealed (the reveal is an ordinary ad-hoc
`clue-reveal` whose clue id is the relation id). `scripts/validate-content.mjs` checks that every `to` resolves and
that nobody points at themself. Scenes: `ambient` is the canonical key; the run view also reads `scene.ambience`
(`scene.ambient ?? scene.ambience`) and maps aliases through `mechanicsUtils.ambientPreset`, but the schema only
lists `ambient`.

## Content loading

- Bundled: `import.meta.glob('../universes/*/content/*.json', { eager: true })`.
- Runtime: `GET /api/content/:universe` → `{ universe, source: 'runtime', packs: [full packs] }` from
  `web app/content/<universe>/*.json` — RUNTIME packs only (bundled packs live in the client bundle).
  `GET /api/content/:universe/:id` → pack; `PUT /api/content/:universe/:id` writes (schema-validated,
  422 `{ error, errors[] }` on failure; `meta.source: "bundled"` is rewritten to `"custom"`);
  `DELETE` removes. `content/examples/` is not a universe and is never listed.
- `ContentContext` exposes `{ packs, byId, save, remove, reload, loading, error, runtimeIds, bundledIds }`
  for the ACTIVE universe, runtime overriding bundled on id collision.

## Sessions

- `create-game` takes `{ universeId, packId? }`; the game object stores both; the callback and the
  `join-game` response include `{ universeId, packId }` so the player's device themes itself.
- Players are universe-agnostic: `{ id, name, character, tracks: {key: n}, trackMax: {key: n},
  statusEffects[], inventory[], alive, conditions: {name: bool} }`. `assign-character` carries
  `{ character, tracks, trackMax, conditions[] }` computed client-side from `universe.rules`
  (`rulesUtils.initialCharacterState`); `update-player` accepts `updates.tracks` (clamped to trackMax).
- Messages carry `type: 'gm' | 'player' | 'p2p'` and `from: 'GM'` for game-master messages; clients
  render the sender with `terminal.name` and wording from `terms`.
- Session persistence (implemented in `server/persistence.js` + `server/sessions.js`):
  - Every game is snapshotted to `<DATA_DIR>/sessions/<CODE>.json` (`DATA_DIR` env, default `web app/data`,
    git-ignored). Writes are debounced (<= 1 per 250 ms per game) and atomic (tmp + rename); Maps/Sets are
    stored as arrays. On start, snapshots newer than 24 h load as `status: 'dormant'` (no sockets); older
    ones are deleted. Dormant games with no activity for 24 h are swept (at start, every 10 min, and before
    a create-game would hit `MAX_GAMES`); EMPTY dormant games (no seats, no messages, <= 1 log entry) go after 1 h.
  - Game record: `{ code, universeId, packId, status: 'live'|'dormant', createdAt, updatedAt, dmToken, gmPin,
    dmId (socket or null), players: Map<stableId, player>, messages }` (assigned character ids are recomputed from the
    seats; the snapshot keeps an informational `assignedCharacterIds` array). `gmPin` is a 6-digit PIN minted at
    `create-game` (older snapshots get one on load).
    Player `id` is a STABLE id (`p_<hex>`), not the socket id; the record also holds `playerToken`,
    `socketId`, `connected`. Message `fromId`/`toId` are stable player ids, `'dm'` or `'broadcast'`.
  - Events (client -> server, ack callback in parentheses):
    - `create-game { universeId, packId? }` (`{ code, universeId, packId, dmToken, gmPin }` | `{ error }` when the server
      already hosts `MAX_GAMES` live+dormant games — env, default 50)
    - `resume-game { code, dmToken }` (`{ success, code, universeId, packId, dmToken, gmPin, takeover: false, players,
      messages<=200, table, log }` | `{ error }`) or TAKE OVER `{ code, takeover: true, pin }`: the PIN must match the game's
      `gmPin` (5 wrong PINs lock that game's PIN for 60 s); allowed even while another DM socket is attached. A takeover
      ROTATES `dmToken` (the old one is rejected from then on), the previous DM socket gets `session-taken`, and the ack
      carries the NEW `dmToken` (+ `takeover: true`). Pending seat claims are re-sent to the DM after any resume.
    - `end-game { code, dmToken }` (`{ success }` | `{ error }`) — notifies players + board with `game-ended`, makes every
      socket leave the game and board rooms, clears their `socket.data`, closes pending claims, deletes the snapshot
    - `list-resumable { tokens: { CODE: dmToken }, code?, pin? }` (`[ { code, universeId, packId, players, updatedAt, status,
      dmConnected } ]`) — only games whose `dmToken` (or code + GM PIN) the caller presents; otherwise `[]`
    - `join-game { code, playerName }` (`{ success, playerId, playerToken, rejoined: false, player, messages: [], universeId, packId,
      table, dmConnected }` | `{ error }`) — always a NEW seat. A name already seated (trimmed, case-insensitive) answers
      `{ error: 'NAME IN USE — PICK ANOTHER OR ASK THE GM TO RESEAT YOU.', code: 'NAME_IN_USE' }`; max 40 seats.
    - `rejoin-game { code, playerToken }` (`{ success, playerId, playerToken, player, messages<=200, dmConnected, universeId, packId, table }`)
      or `{ code, playerName }` without a valid token = a SEAT CLAIM (`{ pending: true, claimId, name, dmConnected, expiresIn }`):
      the DM gets `seat-claim`; the claimant later gets `seat-claim-result`. Claims wait for an offline DM and fail after
      `SEAT_CLAIM_MS` (env, default 2 min); one pending claim per socket, ≤ 10 per game; a claimant disconnect cancels it.
    - `seat-claim-resolve { gameCode?, claimId, approve }` (DM; `{ success, approved }`) — approve rotates the seat's
      `playerToken`, moves the claimant into the seat and sends the previous device `session-taken`.
  - Events (server -> client): `game-saved { code, savedAt }` (DM, throttled 1/s), `dm-disconnected` / `dm-reconnected`
    (players), `player-left { playerId, playerName, dormant: true, players }`, `player-joined { player, players, rejoined? }`,
    `session-taken` (a GM takeover or a GM-approved seat claim moved this DM/player seat elsewhere), `player-list` entries gain
    `connected`, `seat-claim { claimId, name, playerId, seatConnected, at, expiresAt }` / `seat-claim-closed { claimId }` (DM),
    `seat-claim-result { claimId, approved, error? | success, playerId, playerToken, player, messages, table, dmConnected,
    universeId, packId }` (claimant). Player data (`players` map, `player`) gains `connected`.
  - One socket, one role, one game: `create-game`, `join-game`, `join-board`, `resume-game`, `rejoin-game` (and an approved
    claim) first detach the socket from any OTHER game/role it holds — a DM socket leaves its game dormant (`dmId = null`,
    players get `dm-disconnected`), a player seat goes `connected: false` (`player-left` to that DM), a board leaves the board room.
  - Hardening (`docs/REVIEW_2026-10-30.md`): every handler is registered through `server/guard.js` `safeOn` (non-plain-object
    payloads become `{}`, the ack is used only if it is a function, try/catch logs `[SOCKET] handler "<event>" failed`).
    `guard.EVENT_NAMES` (re-exported by `sessions.js`) lists every client → server event; the server warns on drift.
    `server/index.js` logs `uncaughtException` / `unhandledRejection` and keeps serving (listen errors flush snapshots and exit).
    Ids used as object keys never accept `__proto__` / `constructor` / `prototype` (`asId`, token/room/level/map ids, pool and
    supply keys, condition/track names); `board.tokens` / `board.rooms` are null-prototype objects (snapshots are converted on load

## Generator

- `POST /api/generate` body: `{ universeId, params }` → streams progress, returns a validated pack.
- Uses `@anthropic-ai/sdk` with `claude-opus-5-5`, structured output against the pack schema,
  streaming (long output), `fallbacks: "default"` with beta `server-side-fallback-2026-07-01`.
- The system prompt = engine instructions (schema, quality bar, pacing rules) + `universe.generator.systemPrompt`.
- Note: the pack schema uses `if/then` (acts required for scenario/campaign; ascii/src required by
  map kind), `pattern`, `format: date-time` and open maps. If the structured-output feature rejects
  any of these, send a simplified copy to the model and keep full ajv validation on the result.
- Implemented in `server/generate.js` + `server/generator/` (`core.js`, `prompt.js`, `params.js`, `outputSchema.js`, `universes.js`, `env.js`, `__mock__.js`). Config: `ANTHROPIC_API_KEY`,
  `GENERATOR_MODEL`, `GENERATOR_EFFORT`, `GENERATOR_MAX_TOKENS`, `GENERATOR_FALLBACKS`, `GENERATOR_MOCK`, `GENERATOR_MOCK_DELAY`, `GENERATOR_MAX_CONCURRENT` (see README). `GET /api/generate/status`
  reports `{ configured, mock, model, effort, fallbacks }`; without a key and not in mock mode `POST` answers 400 `generator_not_configured`. The client is `GameNightWizard.jsx` + `wizard/generateClient.js`.
- Also usable from the CLI (run in `web app/`): `node scripts/generate-pack.mjs --universe alien --players 4 ...` (`--dry-run` prints the request).
- Also usable from Claude Code: `.claude/skills/gamenight/SKILL.md` documents how to write a pack
  by hand from the schema without the API (for sessions where the author is Claude itself).

## Theming

`UniverseContext` sets every `theme.vars` entry on `document.documentElement.style` when the
active universe changes, swaps the Google Fonts `<link id="universe-fonts">`, applies the overlay
hook (`theme.overlay` `'crt'` | `'grain'` toggles `html.overlay-<name>`, plus the legacy `crt` class;
`theme.overlayCss` is injected as `<style id="universe-overlay">`), sets the document title and the
inline-SVG favicon (`theme.favicon`) and hands `theme.sfx` to `engine/sfx.js`. Per-device
REDUCE FX / MUTE toggles (`html.fx-reduced`, `localStorage`) switch overlays, animation and sound off.
The table board reads its palette from `theme.board` (a map definition may override it).
Components use only CSS vars and
`var(--font-display)` / `var(--font-mono)`; never hard-code `'Orbitron'` or `#00d4aa` again
(use `color-mix(in srgb, var(--accent) N%, transparent)` for translucent tints).

**Landing.** Every fresh load shows `UniverseSelect` (neutral theme, `UniverseContext.NEUTRAL`):
one card per registry universe, each previewed in its own theme via card-scoped CSS vars, with a
systems line derived from `rules` and a "NO SCENARIOS — GENERATE ONE" hint when the universe has no
bundled scenario packs. Picking a card calls `setUniverseId(id, { boot: true })` → re-theme + an
~800 ms `BootOverlay` ("INITIALIZING <terminal.name>…" + `terminal.statusLines`), then the themed
SessionScreen. "CHANGE UNIVERSE" on the SessionScreen calls `resetUniverse()`. The last choice is
remembered in localStorage only to highlight its card. `?join=CODE` skips the landing and stays
neutral until the server's join response sets the universe. `useUniverse()` returns
`{ universe, universeId, setUniverseId(id, {boot}), universes: [...], chosen, resetUniverse, booting, display }`
where `display` is the neutral pseudo-universe until one is chosen (use it for chrome wording).

## Conventions

- ESM everywhere, no TypeScript, React 19 function components, no new UI libraries.
- Keep the terminal aesthetic; universes change palette/fonts/wording, not layout.
- Mobile first for `PlayerView` (phones at the table). DM views are desktop/tablet.
- Every new feature ships with a smoke check in `scripts/smoke.mjs` (node, no browser) where it can.

## Deviations from the original plan

Where the code differs from what earlier versions of this document (or `docs/BOARD_AND_BUILDER.md`) promised. Check here before assuming.

- **Scripts location.** The target layout put the validator and smoke script in `web app/scripts/`; that is where they are. Repo-level tooling (deploy, art pipeline, catalog validator) is in the root `scripts/`.
- **Cheat sheets** are JSX components (`components/CheatSheets.jsx`, `DuneCheatSheets.jsx`), not a `reference/cheatSheets.js` data file.
- **Wizard and generator** are built (`GameNightWizard.jsx`, `server/generator/`); the earlier "not yet built" and "501 stub" notes are obsolete.
- **Board level** is a separate `board.level` field, not part of `mapId` (`docs/BOARD_AND_BUILDER.md` section 2).
- **Name rejoin** no longer re-attaches automatically: a player's phone re-attaches with its private seat token only; a name-only rejoin is a seat claim the GM approves (`docs/REVIEW_2026-10-30.md` #3). Section 19 of the research backlog said "reconnect by name".
- **GM takeover** needs the per-game 6-digit `gmPin` (not just "no DM connected") and rotates `dmToken`.
- **Bundled packs** are validated with `meta.source: "bundled"` and live in the client bundle; runtime packs override them by id. Map overlay packs (`kind: "maps"`, id `<packId>-maps`, written by the room editor for bundled packs) are a fourth schema `kind`; `ContentContext` merges their `maps[]` into `<packId>` by map id and does not list them as packs.
- **Pack schema vs. universe map data.** Pack `maps[]` may now carry `levelNoun`, `backdrop` (`space`|`sand`|`none`) and `palette` like universe maps (additive; the generator output schema strips them together with `grid`/`outline`/`crop`). Without them a pack map still takes them from the universe map or engine config with the same id (`board/mapDefs.js`).
- **ASCII maps are vector maps on the board.** `kind:"ascii"` maps are parsed by `src/engine/maps/asciiMap.js` (rooms matched to `maps[].rooms` names, ids = hint id or kebab of the name) and drawn by `board/AsciiLayer.jsx` (TV, GM controller, Room Editor, GM Maps tab with a SHOW ASCII toggle). The DM client sends the parsed room rects in `board-set-map`, so fog / auto-reveal / hit-testing need no server change. A cell is 12 × 24 map px; the parser pads the grid (1 row above, 2 below, 2 columns each side). Coverage: `node scripts/test-ascii-maps.mjs`.
- **Initiative deck range** for ALIEN (cards 1-10) is flagged VERIFY in `universes/alien/rules.js`; it is not in the catalog rules.
- **No QR for the join link.** The only QR is the TV link in the Board tab (`board/qr.js`).
- **Not built** (see `docs/FEATURES.md`): `tables[]` in packs, calibration, zone overlay, party view, XP, undo, "previously on" screen, Dune conflict runner, traits and assets.
